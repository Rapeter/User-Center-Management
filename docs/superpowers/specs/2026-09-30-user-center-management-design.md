# 用户中心管理项目整合与补全设计

日期：2026-09-30

## 目标

将本地提供的用户中心后端与 React 前端整理到指定的空 GitHub 仓库，补齐源码中已有但未接通的基础用户管理流程，并提供一份按调用链学习源码的中文路线文档。实现保持原项目技术栈，避免把不同教程版本混成一个应用。

## 采用的源码与目录

采用：

- `user-center-backend-master.zip`：Spring Boot 2.6.4、Java 8、MyBatis-Plus、MySQL 后端。
- `user-center-frontend-master.zip`：React 17、Umi 3、Ant Design Pro 前端。

目标目录：

```text
backend/                 后端 Maven 项目
frontend/                React 前端
README.md                 仓库启动、配置和项目结构说明
源码学习路线.md           分阶段学习内容、调用链和源码位置
backend/sql/             用户表初始化脚本（随完整后端源码保留）
docs/superpowers/specs/   本设计稿
```

Vue 3 前端和两个通用初始化模板不纳入本次仓库，避免出现两个默认前端和未使用的模板代码。保留上游项目的作者标注及现有测试源码。

## 功能范围

### 后端

- 注册接口对空参数及业务校验失败返回统一业务错误；不能把 `-1` 当成注册成功的数据返回。
- 登录失败返回明确的未登录/凭据错误响应，前端能显示失败提示。
- 查询当前用户时重新读取数据库；用户记录已不存在或已逻辑删除时清除失效 Session 并返回未登录错误。
- 保留后端管理员权限校验、逻辑删除和当前 API 路由，不增加新的角色或权限模型。

### React 前端

- 用户管理表格将用户名查询条件传给现有搜索接口。
- 删除操作调用现有管理员删除接口，要求二次确认，并在成功后刷新表格。
- 移除没有对应后端能力的占位编辑/查看操作，避免页面提供无效入口。
- 登录失败时展示明确提示；保留注册、登录、登出和当前用户请求的原有流程。

### 配置与文档

- 将后端线上数据库连接信息改为从环境变量读取，不在仓库保留源码包中的生产凭据；本地配置使用可覆盖的环境变量，并在 README 给出运行配置说明。
- 将前端生产 API 地址改为可配置项，默认使用同源 `/api` 路由，避免请求到源码包原有的外部服务。
- 根 README 说明技术栈、目录、数据库初始化、启动顺序及前后端 API 路由关系。
- `源码学习路线.md` 按数据库与实体、Mapper/Service、Controller 与异常、Session 登录态、React 路由与页面、前后端联调的顺序，标出仓库内具体文件路径，并附练习题。

## 主要调用链

```text
React 页面
  -> frontend/src/services/ant-design-pro/api.ts
  -> frontend/src/plugins/globalRequest.ts
  -> /api/user/*
  -> UserController
  -> UserService / UserServiceImpl
  -> UserMapper + MyBatis-Plus
  -> MySQL 的 user 表
```

注册、登录、当前用户、登出和管理员用户查询/删除都以这条链路作为实现与学习文档的组织方式。管理员查询与删除仍由后端 Session 中的角色校验兜底，前端路由权限只负责页面入口控制。

## 错误处理与配置约定

接口错误继续使用现有 `BaseResponse`、`ErrorCode`、`BusinessException` 和全局异常处理器。新增/调整的错误应提供可读描述；前端请求拦截器负责统一显示接口错误，页面负责显示本地校验和操作结果。

后端生产配置从 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 读取。前端生产构建通过 `REACT_APP_API_BASE_URL` 配置 API 基址，未配置时使用相对 `/api` 路径。跨域部署需要由部署侧提供正确的同源反向代理或匹配的跨域 Session 配置；README 以同源反向代理作为默认建议。

## 测试与范围边界

保留源码包中现有的 Java 测试文件。本次不新增或运行测试。不会升级 Spring Boot、Java、React 或 Umi 版本，不重写密码存储算法，不增加资料包之外的注册字段、分页接口或用户编辑能力。学习路线会指出固定盐 MD5 等现有实现的改进方向，但不在本次范围内改造。

## 完成标准

- 仓库包含可辨认的后端、React 前端及根级运行说明。
- 管理员可以按用户名查询并确认删除用户；非管理员请求仍由后端拒绝。
- 注册、登录和当前用户接口对失败情形返回一致且可读的错误。
- 仓库不包含源码包中的生产数据库凭据，也不再默认请求旧的外部 API 主机。
- `源码学习路线.md` 指向仓库内真实源码位置，并能按调用链安排学习顺序。
- 所有代码和 Markdown 文档最终提交并推送至 `Rapeter/User-Center-Management`。
